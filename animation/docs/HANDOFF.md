## Для ИИ: что это за проект

Покадровое воссоздание четырёх аниме-клипов «Yuta vs. Ryu end fight scene» (Jujutsu Kaisen) в Roblox Studio.
Стиль «Кино» (cinema): реалистичный свет, густой туман над бетонной эстакадой в туманном городе (снега нет),
глубина резкости, неоновые эффекты с bloom. Части: 1 — 58.53 с, 2 — 59.17 с, 3 — 56.87 с, 4 — 44.7 с.
Начала частей 2–4 повторяют конец предыдущей части (как в оригиналах).

Язык общения с заказчиком — **русский**. Правила заказчика:
- если непонятно, что в кадре или как сделать — **спросить**, не додумывать;
- персонажи живые: ветер в волосах, мехе и куртках, инерция, движение всем телом, мелкие движения не пропускать;
- без пальто; торсы треугольные; карта — бетонная эстакада в туманном городе, без снега;
- каждое замечание: записать в `docs/remarks.md` (со скриншотами в `docs/remarks/`), сделать, проверить по кадрам
  оригинала рядом с нашими, перерендерить, отправить видео.

## Инструменты

Нужны: **Rojo 7.7**, **Lune 0.10**, **luau-lsp 1.70** (с `globalTypes.d.luau` для Roblox), **Node 22** +
`npm install` в `tools/preview` (three.js 0.170), **Playwright с Chromium**, **ffmpeg**.
В исходной среде бинарники лежали в `../.tools/` (рядом с папкой `animation`, в git не входят) — их надо установить заново.

- `tools/analyze.sh` — строгая проверка типов (должно быть 0 ошибок и предупреждений).
- `tools/build.sh` — проверка типов, проверка Realizer для частей 1–4, сборка `.rbxl` и проверка мест.
- Превью вне Roblox: `PART=N lune run tools/export.luau build/partN.jsonl 30` → `node tools/preview/render.cjs build/partN.jsonl build/frames_partN 1280 720`
  → ffmpeg в MP4. Быстрые отдельные кадры: `PART=N lune run tools/export_times.luau out.json t1 t2 …` и тот же render.cjs.
- Сравнение с оригиналом: `tools/preview/compare.sh <оригинал> <превью> <выход> <crop>`.
  Кропы картинки оригиналов (видео вертикальные 720x1280 / 1080x1920): ч.1 `1080:626:0:647`, ч.2 `720:416:0:432`,
  ч.3 `720:448:0:400`, ч.4 `720:416:0:432`.
- Общее видео: кадры частей подряд — ч.1 кадры 0–1755, ч.2 157–1764, ч.3 79–1705, ч.4 со 167 до конца
  (повторы в начале частей выкидываются), 30 к/с.

## Соглашения (важно, иначе всё поедет)

- **Знаки поворотов `Rig.R`:** торс/голова −x наклон вперёд, +x назад; +y поворот влево персонажа;
  руки/ноги +x вперёд; правая рука в сторону +z, левая −z; локти +x, колени −x. Позы можно сдвигать
  (`C(0, 0.1, -0.3) * R(…)` — сдвиг сустава).
- Корень персонажа — точка на земле под тазом; персонаж смотрит в −Z.
- **Использовать `Util.lookAt`, не `CFrame.lookAt`** (в Lune он перевёрнут).
- Время детерминированно; план — `{ id, t0, t1, run(ctx) }`; `Timeline.find` берёт последний начавшийся план.
- Случайность: `Util.rng` (Park–Miller); у близких сидов первое значение почти одинаковое — сид разносить и
  пару значений пропускать (см. локальные `rng(seed)`).
- Свойства (`ctx:prop`) действуют только в этом кадре.
- Время в CapCut у заказчика — это время общего видео: ч.1 0:00–0:58.5 (t = общее), ч.2 0:58.5–1:52.1
  (t = общее − 53.3), ч.3 1:52.1–2:46.4 (t = общее − 109.5), ч.4 2:46.4–3:25.5 (t = общее − 160.8).
  Время у заказчика обычно на ~1 с раньше — план всегда сверять по картинке.

## Как работать с замечаниями

1. Найти план по картинке (не только по времени), вырезать кадры оригинала (`ffmpeg -ss … -vf crop=…`) и наши,
   положить рядом, разобрать покадрово, что не так.
2. Записать строку в `docs/remarks.md` (№, время, часть/план/файл, замечание, что выяснили, что сделать, статус)
   и скриншоты в `docs/remarks/NN_*`.
3. Исправить код, `tools/analyze.sh` (0 замечаний), проверить кадрами рядом с оригиналом.
4. `tools/build.sh`, перерендерить часть, пересобрать общее видео, положить в `preview/`, закоммитить, отправить заказчику.
